# FragrancedByMeena

A mobile-first Ghana fragrance store with a Next.js/TypeScript storefront and FastAPI/SQLAlchemy API. The initial release supports a real database-backed catalogue, protected store management, guest order requests and WhatsApp confirmation. No live financial transactions are processed.

## Included

- Chocolate, ivory and champagne visual identity, responsive catalogue, brand/category search and sorting.
- Seed catalogue from the supplied brief, with **no invented prices or stock**. Uploaded reference photographs require permission before inclusion in this public repository; the current release uses labelled neutral illustrations.
- Product detail URLs, editable SEO metadata, Product JSON-LD, sitemap and robots.
- Browser-saved cart and wishlist; server-side checkout validates current price, visibility, stock and configured delivery fees.
- Unique order reference and private tracking key, WhatsApp confirmation and customer contact shortcuts.
- Admin product create/edit/delete/duplicate/publish, multiple image uploads via Cloudinary, pricing, stock, fragrance notes, featured and new-arrival flags.
- Admin order management with transactional inventory deduction on confirmation and restoration on cancellation/return.
- Brand/category additions and deactivation, article publishing, delivery areas, homepage announcement/hero settings, contact inbox and consented newsletter records.
- Initial admin setup from environment variables, Argon2 password hashing, signed expiring access tokens, protected admin API, basic request limiting, security headers and restricted CORS.
- Payment-provider interface prepared; all payment statuses remain Pending.

## Local setup

Python 3.12+ and Node.js 22 are recommended.

```bash
python -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cd backend
export INITIAL_ADMIN_EMAIL='your-email@example.com'
export INITIAL_ADMIN_PASSWORD='choose-a-strong-unique-password'
export JWT_SECRET='generate-a-long-random-secret'
../.venv/bin/uvicorn app.main:app --reload
```

Local development defaults to SQLite. These exported values are illustrative, not permanent credentials. Use environment variables or a secrets manager and never commit real secrets.

In a second terminal:

```bash
cd frontend
npm ci
npm run dev
```

Open http://localhost:3000 and http://localhost:3000/admin. Change the initial password under Security, then remove INITIAL_ADMIN_PASSWORD from the service configuration. The initialization code does not overwrite an existing account.

## Neon PostgreSQL

Create a dedicated Neon database for this project. Set backend DATABASE_URL to its PostgreSQL connection string with TLS (`sslmode=require`). Both `postgresql://` and `postgresql+psycopg://` forms are supported. Set a stable JWT_SECRET. Startup creates the initial tables and inserts the catalogue only if no products exist.

Do not use SQLite on Render: its filesystem is ephemeral. PostgreSQL is required for durable orders and content. Schema creation is an initial MVP bootstrap; use reviewed Alembic migrations before modifying an existing production schema.

## Render

`render.yaml` defines two free web services. It does not create or connect a Neon project automatically.

1. Connect this repository in Render using New → Blueprint.
2. Set API DATABASE_URL to the dedicated Neon TLS connection string, INITIAL_ADMIN_EMAIL, a strong INITIAL_ADMIN_PASSWORD, and Cloudinary credentials if photo uploads are needed. JWT_SECRET is generated by the Blueprint.
3. Set API FRONTEND_URL to the actual storefront URL, without a trailing slash.
4. Set storefront NEXT_PUBLIC_API_URL to the actual API URL, without a trailing slash. Set NEXT_PUBLIC_SITE_URL to the storefront URL. Public values are included in the frontend build, so rebuild after changing them.
5. Optionally set NEXT_PUBLIC_GOOGLE_MAPS_EMBED_URL to an approved embed URL for the exact location pin. The default map searches the supplied business area and is not a verified exact pin.
6. Check `/api/health`, catalogue, admin login, delivery configuration, product editing, order submission and confirmation. Free services may take time to wake after inactivity.
7. Change the initial admin password and remove the initial password variable.

## Images

Approved static product images can be shipped with the storefront. The reference-image seed mapping is disabled unless INCLUDE_REFERENCE_IMAGES=true and the approved WebP files are present. Admin uploads use Cloudinary (`CLOUDINARY_URL`) and reject unsupported file signatures and files over 5 MB. Alternatively, enter HTTPS image URLs. Uploads return WebP URLs. No product imagery is invented. Products without supplied photos use labelled neutral illustrations.

## Payments

Mobile Money (MTN, Telecel, AT Money) and card payments show “Integration Coming Soon”. Checkout creates an **unpaid order request**. The backend deliberately provides no API to set an order to Paid.

`backend/app/payments.py` defines the provider boundary. To connect a real provider, add persistent payment transactions, signed webhook validation, replay/idempotency protection, amount/currency reconciliation and provider-specific tests. Environment placeholders are provided; entering keys alone will not activate payment processing.

## Validation

```bash
cd backend
../.venv/bin/python -m pytest -q
cd ../frontend
npm run typecheck
npm run build
```

The API tests cover admin authorization, unknown-price/out-of-stock rejection, private tracking, delivery-fee validation, repeat-confirmation inventory behavior, cancellation restoration and a competing order losing confirmation when stock is exhausted.

## Scope and remaining work

This is the initial functional MVP, not completion of every advanced item in the 57-section brief. Before production, complete:

- Customer account registration, email verification/reset, persistent customer addresses and account-linked order history/wishlist.
- Product variants, preorders, discounts/bundle pricing, formal collection membership, review moderation and full blog editing.
- Fine-grained staff permissions, audit trails, durable/distributed rate limiting, token revocation, structured content schemas and production migration tooling.
- Live gateway integration, payment reconciliation/refunds, notifications and email delivery.
- Full SSR catalogue pagination, additional filters/autocomplete, individual blog/collection routes, optimized Next/Image delivery, complete schema coverage and measured Core Web Vitals/accessibility QA.
- Owner-supplied prices, sizes, stock, fragrance notes, delivery rates and approved legal policies. Verify business location pin and authenticity claims before publishing them.

Newsletter/contact entries are stored and visible in admin; no email is sent. Delivery fees are configured by the owner. The homepage does not show invented reviews or business sales statistics. Role labels exist, but the current admin roles share management access; restricted staff permissions remain future work.
